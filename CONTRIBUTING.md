# Contributing

Thanks for helping improve VideoToolbox Remote.

## Useful Starting Points

- [Development guide](docs/development.md) for build, test, benchmark, and release notes workflows.
- [Protocol spec](docs/protocol.md) for wire format and compatibility rules.
- [Architecture](docs/architecture.md) for client/server data flow.
- [Troubleshooting](docs/troubleshooting.md) for common environment issues.

## Reporting Bugs

Please include:

- Server platform and hardware, including macOS version and whether it is Apple Silicon or Intel/T2.
- Client platform and architecture.
- VideoToolbox Remote release tag or commit.
- `vtremoted --version`.
- Full FFmpeg command.
- Relevant `vtremoted` and FFmpeg logs.
- Whether the issue reproduces with the latest release.

## Pull Requests

Keep changes focused and include tests or reproduction notes when behavior changes.

For code changes, run the most relevant checks from [Development](docs/development.md). If you cannot run a check locally, say so in the PR and include the reason.

Protocol changes must preserve backwards-compatible negotiation or fail clearly during configure/handshake before frame processing begins.

## Release and Metadata Work

When preparing a release or public-facing documentation change, keep these surfaces aligned:

- `CHANGELOG.md`
- `docs/llms.txt`
- `docs/_config.yml`
- GitHub release notes generated by `scripts/generate_release_notes.sh`
- GitHub metadata managed by `make sync-github-metadata`
